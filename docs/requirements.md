# 요구사항 정의서 (Software Requirements Specification)

**프로젝트:** PoseFit (포즈핏) — AI 기반 운동 자세 분석 및 피드백 서비스
**문서 버전:** v1.0 (초안)
**작성일:** 2026-05-21
**작성자:** 포즈핏 개발팀
**문서 상태:** 기능 조율 진행 중

---

## 1. 프로젝트 개요

### 1.1 프로젝트 명
포즈핏 (PoseFit) — AI 기반 운동 자세 분석 및 피드백 웹 서비스

### 1.2 프로젝트 목적
사용자가 웹캠을 통해 운동 동작을 수행하면, AI 비전 알고리즘이 실시간으로 자세를 분석하고 정답 영상과의 비교를 통해 개인화된 피드백을 제공한다. 헬스장이나 PT 없이도 가정에서 정확한 자세로 운동할 수 있도록 돕는 것을 목표로 한다.

### 1.3 서비스 흐름 요약
로그인 → 메인(대시보드) → 운동 선택 → 카메라 인식 및 시작 → AI 동작 분석 → 종료 및 리포트 확인 → 보고 화면(히스토리/통계 조회)

### 1.4 기술 스택

| 구분 | 선택 후보 및 비고 |
| --- | --- |
| 프론트엔드 | Next.js, TailwindCSS |
| 백엔드 | FastAPI |
| 데이터베이스 | MySQL |
| 객체 트래킹 (검토 중) | OpenCV CSRT / YOLO + ByteTracker / YOLO + OSTrack / SAM2 |
| 포즈 추정 (검토 중) | OpenPose / YOLO-Pose / PoseNet / MoveNet / MediaPipe Pose / Kakao Pose |
| LLM | 운동 피드백 자연어 생성용 (모델 미정) |
| 인프라 (예정) | 추후 결정 |

### 1.5 용어 정의

| 용어 | 설명 |
| --- | --- |
| 바운딩 박스 | 객체 탐지 결과로 그려지는 사각형 영역. 사용자의 신체를 화면에서 추출하는 데 사용된다. |
| 포즈 추정 (Pose Estimation) | 이미지/영상에서 사람의 관절 좌표를 추출하는 기술. |
| 키포인트 | 포즈 추정으로 얻어지는 관절 좌표점 (어깨, 팔꿈치, 무릎 등). |
| 정답 영상 | 각 운동의 모범 자세를 담은 기준 영상으로, 사용자 자세와 비교 대상이 된다. |
| 좌표 정규화 | 바운딩 박스 크기에 맞춰 키포인트 좌표를 0~1 범위로 변환하여, 카메라 거리·해상도와 무관하게 자세를 비교할 수 있도록 하는 과정. |
| 리포트 | 1회 운동 수행 후 또는 일/주/월 단위로 산출되는 분석 결과(점수, 피드백). |

## 2. 사용자 정의

### 2.1 타깃 사용자
- **홈트레이닝 입문자:** 자세가 맞는지 확인할 사람이 없는 1인 운동자
- **운동 자세 교정이 필요한 사람:** 헬스 초·중급자
- **운동 기록을 정량적으로 관리하고 싶은 사람**

### 2.2 사용자 권한

| 역할 | 권한 범위 |
| --- | --- |
| 비회원 | 랜딩/소개 페이지 열람만 가능. 운동 분석 기능 사용 불가. |
| 회원 (일반 사용자) | 회원가입(얼굴 캡처 포함), 로그인, 운동 수행, 영상 저장, 본인 리포트 조회. |
| 관리자 (운영자) | 운동 종목 추가/수정, 정답 영상 등록, 회원 관리, 시스템 모니터링. (Phase 2) |

## 4. 기능 요구사항

기능은 4개 영역으로 분류한다: **인증(AUTH), 메인(MAIN), 운동(EX), 보고(REP)**.

### 4.1 인증 (AUTH)

| ID | 기능명 | 상세 설명 | 우선순위 |
| --- | --- | --- | --- |
| AUTH-01 | 로그인 | 소셜 계정(구글, 카카오) 기반 로그인. 세션 또는 JWT 발급. | 필수 |
| AUTH-02 | 회원가입 | 소셜 계정(구글, 카카오) 연동 후 닉네임 입력 및 가입. | 필수 |
| AUTH-03 | 얼굴 캡처 | 회원가입 단계에서 사용자의 얼굴을 캡처하여 등록. 운동 시작 시 얼굴 인식으로 사용자를 식별하는 용도. | 필수 |
| AUTH-04 | 로그아웃 | 세션/토큰 만료 처리. | 필수 |
| AUTH-05 | 비밀번호 찾기/변경 | 이메일 인증 기반 비밀번호 재설정. | 선택 |

#### 4.1.1 얼굴 캡처 상세
- 회원가입 마지막 단계에서 웹캠 권한 요청 후, 정면 얼굴 사진을 자동 캡처한다.
- 캡처된 얼굴 임베딩(특징 벡터)을 서버에 저장하며, 원본 이미지의 저장 여부 및 보관 기간은 개인정보 보호 정책에 따라 결정한다.
- 얼굴이 검출되지 않거나 다수 검출 시 재촬영을 안내한다.
- 운동 시작(START) 시점에 카메라에 들어온 얼굴과 등록된 얼굴을 매칭하여, 등록된 사용자에게 바운딩 박스 ID를 부여한다.

### 4.2 메인 / 대시보드 (MAIN)

| ID | 기능명 | 상세 설명 | 우선순위 |
| --- | --- | --- | --- |
| MAIN-01 | 대시보드 표시 | 로그인 후 진입하는 메인 화면. 최근 운동 데이터 요약(최근 점수, 운동 횟수 등)을 카드 형태로 표시. | 필수 |
| MAIN-02 | 이전 운동 데이터 보기 | 최근 N건의 운동 기록을 시간순으로 표시. 클릭 시 해당 운동의 리포트로 이동. | 필수 |
| MAIN-03 | 운동하기 진입 | 운동 선택 화면(SCR-03)으로 이동. | 필수 |
| MAIN-04 | 리포트 진입 | 보고 화면(SCR-07)으로 이동. | 필수 |
| MAIN-05 | 설정 진입 | 설정 화면(SCR-08)으로 이동. | 필수 |
| MAIN-06 | 히스토리 요약 | 최근 7일/30일 활동 캘린더 또는 그래프 표시. | 선택 |

### 4.3 운동 (EX) — 핵심 기능

운동 기능은 본 서비스의 핵심으로, 다음 하위 단계를 모두 포함한다.

| ID | 기능명 | 상세 설명 | 우선순위 |
| --- | --- | --- | --- |
| EX-01 | 운동 선택 | 지원하는 운동 종목을 카드 형태로 나열(푸쉬업, 런지 등). 선택 시 해당 운동 세부 화면으로 이동. | 필수 |
| EX-02 | 이전(정답) 영상 보기 | 선택한 운동의 모범 자세 영상을 재생하여 사용자가 자세를 미리 학습할 수 있도록 한다. | 필수 |
| EX-03 | START — 얼굴 인식 및 ID 부여 | 카메라 프리뷰에서 사용자의 얼굴을 인식하여 등록된 사용자임을 확인하고, 해당 사용자에게 바운딩 박스 ID를 부여한다. 미등록자 또는 다수 인물 인식 시 안내 후 분석 중단. | 필수 |
| EX-04 | 객체 추적 | 부여된 ID를 기준으로 사용자의 신체 영역을 프레임별로 추적한다. (트래커 후보: OpenCV CSRT, YOLO+ByteTracker, YOLO+OSTrack, SAM2 — 성능 테스트 후 선정) | 필수 |
| EX-05 | 포즈 추정 | 추적된 영역 내에서 사용자의 관절 키포인트를 추출한다. (모델 후보: OpenPose, YOLO-Pose, PoseNet, MoveNet, MediaPipe Pose, Kakao Pose — 정확도·속도 비교 후 선정) | 필수 |
| EX-06 | 좌표 정규화 | 바운딩 박스 크기를 기준으로 키포인트 좌표를 정규화(0~1)하여, 카메라 거리·각도·해상도의 영향을 최소화한다. | 필수 |
| EX-07 | 정답 영상과의 좌표 비교 | 정답 영상의 정규화된 좌표 시퀀스와 사용자의 좌표 시퀀스를 프레임 단위로 비교하여 차이(오차)를 계산한다. | 필수 |
| EX-08 | STOP | 사용자가 STOP 버튼을 누르면 영상 캡처와 분석을 중단한다. | 필수 |
| EX-09 | 운동 분석 및 점수 산출 | 수집된 좌표 비교 결과를 바탕으로 운동 점수(예: 100점 만점)를 산출한다. 점수 산정 기준은 별도 정의(평균 각도 오차, 동작 횟수, 자세 유지 시간 등). | 필수 |
| EX-10 | 리포트(피드백) 생성 | LLM 또는 룰 기반으로 사용자에게 보여줄 자연어 피드백을 생성한다 (예: '무릎이 발끝보다 앞으로 나왔습니다'). | 필수 |
| EX-11 | 운동 종료 | 사용자가 명시적으로 운동 종료를 선택할 때까지 결과 화면을 유지한다. | 필수 |
| EX-12 | 영상 저장 | 사용자가 저장을 선택한 경우에만 운동 영상을 서버에 저장한다. 저장하지 않은 영상은 즉시 폐기. | 필수 |

#### 4.3.1 운동 실행 파이프라인 (EX-03 ~ EX-07)
START 버튼 클릭 후 STOP까지의 영상 처리 파이프라인은 다음 순서로 진행된다:

1. **1단계:** 얼굴 인식 → 등록 사용자 식별 및 바운딩 박스 ID 부여
2. **2단계:** 객체 추적 → 매 프레임마다 사용자 위치 갱신
3. **3단계:** 포즈 추정 → 17개 내외 관절 키포인트 추출
4. **4단계:** 좌표 정규화 → 바운딩 박스 기준 0~1 스케일 변환
5. **5단계:** 정답 영상의 키포인트 시퀀스와 DTW(Dynamic Time Warping) 등 알고리즘으로 비교
6. **6단계:** 프레임별 오차 누적 → 최종 점수 및 피드백 생성

#### 4.3.2 지원 운동 종목 (1차 목표)
- 푸쉬업
- 플랭크
- 오버헤드프레스

> ※ 정답 영상이 확보되는 종목 위주로 우선 출시하고, 이후 추가한다.

### 4.4 보고 / 히스토리 (REP)

| ID | 기능명 | 상세 설명 | 우선순위 |
| --- | --- | --- | --- |
| REP-01 | 저장한 영상 보기 | 저장한 운동 영상 목록을 표시하고, 클릭 시 재생. | 필수 |
| REP-02 | 운동별 리포트 | 선택한 운동의 과거 수행 점수 추이를 그래프로 표시. | 필수 |
| REP-03 | 일간 리포트 | 특정 일자의 총 운동 시간, 종목, 점수 요약. | 필수 |
| REP-04 | 주간 리포트 | 주 단위 운동 빈도 및 평균 점수. | 필수 |
| REP-05 | 월간 리포트 | 월 단위 운동 빈도 및 평균 점수, 가장 잘한 운동 등. | 필수 |
| REP-06 | 총점 / 누적 통계 | 전체 기간의 누적 점수, 운동 횟수, 평균 점수. | 필수 |
| REP-07 | 필터별 리포트 | 운동 종목별 필터링하여 위 리포트들을 조회. | 필수 |

## 5. 비기능 요구사항

### 5.1 성능
- 운동 실행 화면의 실시간 분석은 **최소 15 FPS 이상** 유지를 목표로 한다.
- 포즈 추정 모델의 응답 지연(latency)은 **프레임당 100ms 이하**를 목표로 한다.
- 리포트 화면 로딩은 **2초 이내** 완료를 목표로 한다.

### 5.2 보안 / 개인정보
- 얼굴 이미지 및 임베딩은 개인정보로 분류하여 암호화 저장한다.
- 운동 영상은 사용자가 명시적으로 저장한 경우에만 서버에 보관하며, 그 외 영상은 즉시 폐기한다.
- 비밀번호는 해시(bcrypt 등)로 저장한다.
- 회원 탈퇴 시 얼굴 데이터·영상·운동 기록을 일정 기간 내 모두 삭제한다.

### 5.3 사용성
- 주요 동작(운동 시작/종료)은 화면의 큰 버튼으로 명확히 표시한다 (와이어프레임의 START / STOP 강조).
- 카메라 권한 거부, 얼굴 미인식 등 예외 상황에 대한 가이드 메시지를 명확히 제공한다.

### 5.4 호환성
- 최신 Chrome / Edge / Safari 브라우저 지원.
- 데스크탑 우선 / 태블릿 대응. 모바일은 Phase 2.
- 웹캠이 내장된 노트북 또는 외장 웹캠 환경에서 동작해야 한다.

### 5.5 확장성
- 운동 종목 추가가 정답 영상 + 메타데이터 등록만으로 가능하도록 설계.
- 포즈 추정 모델은 추후 교체가 용이하도록 어댑터 패턴 적용.

## 6. 데이터 요구사항 (개요)

MySQL 기반의 주요 엔티티는 다음과 같다. 상세 스키마는 별도 ERD 문서에서 정의한다.

| 엔티티 | 주요 필드 |
| --- | --- |
| User | `id, email, nickname, face_embedding, created_at` |
| Exercise | `id, name, description, reference_video_url, reference_keypoints, difficulty` |
| WorkoutSession | `id, user_id, exercise_id, started_at, ended_at, score, video_url(nullable), saved(bool)` |
| KeypointFrame | `id, session_id, frame_index, keypoints(json), bbox` |
| Feedback | `id, session_id, content(text), generated_by(rule/llm), created_at` |
| Report | `id, user_id, period_type(daily/weekly/monthly), period_start, summary_json` |

## 7. 제약사항 및 가정

### 7.1 제약사항
- 초기 버전은 단일 사용자 환경(웹캠 1대, 1인)에 한정한다.
- 프레임 처리는 클라이언트 또는 서버 중 어디서 수행할지 비전 알고리즘 선정 후 결정한다 (브라우저에서 MediaPipe 실행 vs 서버 추론 비교 필요).
- 정답 영상의 권리(저작권)는 자체 촬영 또는 라이선스 확보된 영상에 한정한다.

### 7.2 가정
- 사용자는 충분한 조명이 있는 환경에서 정면 또는 측면 카메라로 운동을 수행한다.
- 사용자는 자신의 신체가 카메라에 모두 들어오는 위치에서 운동한다.
- 회원가입 시 등록한 얼굴과 운동 시 인식되는 얼굴은 동일한 사용자이다.

## 8. 미정 / 추가 논의 필요 항목

회의 시 명확히 결론나지 않았거나, 추가 조사가 필요한 사항을 정리한다.

| ID | 항목 | 내용 |
| --- | --- | --- |
| T-01 | 비전 모델 선정 | 객체 추적·포즈 추정 모델 후보들의 정확도/속도 벤치마크 필요. 클라이언트 추론(MediaPipe 등)과 서버 추론 비교 포함. |
| T-02 | LLM 모델 선정 | 피드백 생성에 사용할 LLM 모델 및 비용·지연 검토 필요. |
| T-03 | 점수 산정 알고리즘 | 관절 각도, 동작 횟수, 자세 유지 시간 등 어느 요소를 어떤 가중치로 반영할지 결정 필요. |
| T-04 | 정답 영상 확보 방법 | 자체 촬영 vs 외부 라이선스 vs 트레이너 협업 등 결정 필요. |
| T-05 | 얼굴 데이터 보관 정책 | 얼굴 임베딩만 저장할지, 원본 이미지도 저장할지 등 개인정보 정책 확정 필요. |
| T-06 | 운동 종목 1차 확정 | 1차 출시에 포함될 운동 종목 최종 확정 (푸쉬업, 플랭크, 런지, 오버헤드프레스) → 확정 완료 |
| T-07 | 리포트 시각화 방식 | 차트 라이브러리(Recharts, Chart.js 등) 및 그래프 종류 결정 필요. |
| T-08 | 배포 환경 | 프론트·백엔드·DB 배포 인프라(AWS/GCP/자체 서버) 결정 필요. |
